## 坐标、单位和含义

- 机体系随 Pitch 机构运动：X 指向枪口前方，Y 指向右方，Z 指向下方，组成右手系。两传感器必须刚性连接，不能安装在会相对转动的两个机构上。
- 参考系 Z 指向重力方向，X 是初始化完成时枪口的水平朝向。它不随云台转动，不是每周期把姿态重置成零。
- 四元数 `[w,x,y,z]` 主动旋转机体系向量到参考系；标准 ZYX 欧拉角为 Yaw 右转正、Pitch 抬头正、Roll 右倾正。
- 启动只将 Yaw 设零；Pitch/Roll 保留真实倾斜。Yaw 在 ±180° 回绕，`yaw_total_deg` 累加跨界差值；Pitch 约±90°时欧拉角有奇异性，应使用四元数。累计角为 float，长时间多圈运动有精度限制。
- 加速度计测量比力，**水平静止应该是 `[0,0,-9.80665] m/s²`**。融合使用负比力作为重力方向，不能把加速度正负号和陀螺仪安装方向混为一谈。
- 角速度 `rad/s`，公开欧拉角 `degree`，磁场 `μT`，温度 `°C`。原始值仍为芯片系 LSB。

安装转换的矩阵行是云台 X/Y/Z，列是芯片 X/Y/Z：`body = rotation × chip`。矩阵必须正交且 `det=+1`，不能只反转一个轴构成镜像。当前两颗传感器分别按用户映射配置为 `diag(1,-1,-1)`，即芯片X朝前、Y朝左、Z朝上，转换时X保持、Y/Z取反；BMI088的同一个矩阵作用于比力和角速度。两配置保留独立来源和独立验证要求，不能凭封装或相邻位置假定同向。

用户给出的BMI088加速度单位为g，送入本工程融合前应乘9.80665成为m/s²；若角速度已经是rad/s则直接使用。当前正式驱动已经分别输出m/s²、rad/s，应用层只做安装旋转，不再乘这些换算系数。IST8310驱动先将有符号原始值转换成float并乘0.3成为μT；应用层再做芯片系硬铁/软铁标定及安装旋转，`mag_raw`仍保留芯片原始值。不要把-32768的取反结果保存回int16_t，也不要对驱动输出再次乘0.3。

### 2026-10-17 用户轴向观测与待确认项

用户先说明读的是参考工程 `spi_bmi088` 的 `phys`，且是开发板已安装到云台后的读数。该参考 `BMI088_ConvertRawToPhys()` 只乘正比例系数，不旋转坐标：`Acc_X/Y/Z` 单位为mg，`Gyro_X/Y/Z`单位为°/s，符号与芯片原始值相同。用户随后给出的映射代码注明g和rad/s，接入时必须以实际字段单位为准，不能只凭 `phys` 名称判断。固定到云台不会自动改变字段的坐标定义。本工程驱动输出仍是芯片坐标，单位为m/s²和rad/s；`Ins_GetSnapshot()` 的物理向量已转换到前右下机体系并对角速度减去启动零偏。

用户观测为：向机器人前方加速时芯片X增加，向右加速时芯片Y减少，向下加速时芯片Z减少；据此填写上述BMI088候选矩阵。加速度变化应比较加速阶段，匀速平移不会持续产生该增量。水平静止时芯片Z预计约+1g，转换后机体Z约-9.80665m/s²；1g约9.8m/s²，参考 `phys.Acc_Z` 则应约+1000mg，不能写成9.8g。静止X/Y非零还可能来自倾角、固定偏置或噪声，不能仅凭非零断言零漂，也不能随意扣除三轴静止均值以抹掉真实倾角。

此前用户描述陀螺X同向、Y/Z反向，同时又描述“沿机器人正轴从尾看向头，逆时针时三轴读数都减少”，两项描述曾存在视角歧义。当前以用户最新提供的三类传感器逐轴映射为配置依据：比力/角速度/磁场均 `[x,-y,-z]`，不额外叠加其他翻转。完整动作复核尚未记录，安装确认仍关闭，按以下实际动作复核：

| 一次只做一个动作 | 参考工程芯片 `phys` 预期 | 本工程快照机体系角速度预期 |
|---|---|---|
| 云台向右转 | `Gyro_Z` 为负 | `gyro_rad_s[2]` 为正 |
| 枪口抬头 | `Gyro_Y` 为负 | `gyro_rad_s[1]` 为正 |
| 云台右侧下倾 | `Gyro_X` 为正 | `gyro_rad_s[0]` 为正 |

符号指运动引起的变化，需排除静止零偏；动作结束后角速度应回到零偏附近。若不符，先复核观测轴、视角和芯片数据来源，不把非正交或镜像矩阵写入融合。

## 数据链、初始化与失败处理

```text
PC5 DRDY → 整数时间/序号 + 任务通知 → gyro SPI DMA
PC4 DRDY → 最新序号                   → accel SPI DMA
PG3 DRDY → 最新序号 / 5ms状态兜底       → I2C新数据
                                      ↓
     芯片单位 → 标定 → 安装旋转 → 静止零偏 → AHRS → 一致快照
```

1. 任务先验证 CubeMX 配置：Mode3、SPI /16、I2C 400kHz、下降沿及六个相关 IRQ 的使能/优先级5。配置不匹配时快照为 FAULT，任务受控等待；修正后需重新启动。
2. 启用 DWT 周期计数，保留已有计数值。BMI088 初始化产生加速度片选上升沿、软复位、dummy 读、双 ID 检查、逐项配置回读。陀螺 INT3 为低有效推挽；加速度 INT1 同样低有效。
3. 唯一所有者串行启动 gyro/accel/temperature DMA。缓冲长期有效，放主 RAM；任务等待期间释放 CPU。回调只抬片选和通知，不做解析、计算或打印。
4. 每个新陀螺样本产生一次处理；800Hz 比力在 1kHz 陀螺更新间复用最近有效值。事件积压只处理最新值并计丢帧，不循环补跑旧样本。
5. 磁复位低/高各等待50ms，但以分步状态机推进，每次最多一次有界 I2C 事务，不暂停正常融合100ms。无磁数据或总线失败都不阻挡六轴姿态。200Hz 状态兜底每5ms读取一次，NOT_READY 不刷新样本时间；STAT1 bit1 是旧数据覆盖，不是磁饱和。
6. 比力/陀螺掉线、DMA 超时、异常实际间隔使姿态失效，释放片选后等待1s重试 BMI088；成功后重做静止校准并建立新的零航向，`reset_sequence` 加一。不能把恢复后的零点当作与故障前连续。

时间基准：DRDY 同时记录 DWT cycles 和 HAL ms。积分用 `uint32_t(current_cycles-previous_cycles)/SystemCoreClock`，HAL 毫秒差用于新鲜度；另用 HAL 跨帧间隔防止 DWT 约25.6s回绕掩盖长暂停。等待、DMA超时和重试用 FreeRTOS Tick，显式 `pdMS_TO_TICKS()`。时间戳0可能是真实样本，用独立有效位判断首次采样。

温度约每1s读取一次，手册说明内部约1.28s更新；重复使用缓存不会刷新 `temperature_ms`。温度无效码0x80/0x00使 `temperature_valid=false`。零偏没有温度模型。

## 融合和启动标定

连续静止默认2s：角速度模长≤0.05rad/s，比力模长与g相差≤5%，窗口内每轴角速度标准差≤0.005rad/s。运动、比力过期或方差不合格会清窗口。零偏在云台机体系保存，每次输入角速度先减去它。阈值内恒速慢转无法可靠识别；操作者必须保持真正静止。现有电机任务不会被 INS 自动停机，需自行保证标定期间机构不动。

`q_dot = 0.5 * q ⊗ [0,omega]`，使用实际 `dt_s` 积分并归一化。Mahony 重力反馈是测量重力与估计重力的叉积；`Kp=0.5/s`、`Ki=0/s²`。比力模长偏差≤5%时全权重，5~20%线性降权，≥20%拒绝重力校正；只看模长不能识别所有平动加速度。

磁校正前先 `corrected_chip = softiron × (raw_chip - bias)`，再应用磁安装旋转。初始校正磁向量被保存到初始水平参考系中，因此可以约束相对航向，不要求对准磁北。默认磁模长10~100μT、相对初始模长偏差≤25%、水平分量>总模10%、航向创新≤45°才能使用；磁修正≤3°/s，恢复权重用2s升到1。磁误差只沿估计重力轴反馈。

没有磁标定或观测过期/异常时回退六轴，Yaw 可以漂移；比力异常时短时陀螺传播。范围内的干扰仍可能通过门控，特别是电机磁场随转角或电流改变时。首次可用磁样本较晚到达时以当时的参考系建立磁约束，不跳变为磁北。

主要配置均在任务头，宏旁有单位、范围和直接作用：安装/标定开关及矩阵、静止时间/阈值、AHRS增益/积分上限、比力权重、磁模长/创新/速率/恢复门、最大dt、新鲜度和通信超时、重试与日志间隔、器件量程/ODR。修改量程/ODR后必须重新核算DRDY频率、执行预算和阈值；默认组合为±6g/800Hz及±2000°/s/1000Hz/116Hz。

## 公开接口与任务所有权

- `Bmi088_Init/StartRead/FinishRead/Abort`：所有者任务调用；初始化可延时，DMA API 为异步开始/任务解析。`DmaCompleteFromIsr` 只供回调。
- `Ist8310_BeginInit/PollInit/Read`：任务调用；`Init` 是启动时便利阻塞包装，正常融合期间恢复必须使用分步接口。
- `Ahrs_Init/Update/GetEuler`：无 HAL/RTOS，所有状态属于句柄；输入无效或dt超限时 Update 不提交候选状态。
- `Ins_Init/Process/SetFault`：只供唯一 INS 任务。其他任务只调用 `Ins_GetSnapshot()`。

```c
#include "app/ins/ins.h"

Ins_SnapshotTypeDef attitude;
if (Ins_GetSnapshot(&attitude) && attitude.attitude_valid) {
  /* 可以读取一致的 attitude.q、yaw_deg、pitch_deg 等。
   * 后续控制接入必须同时处理 reset_sequence 改变。
   */
}
```

快照含原始/机体系观测、减偏角速度、机体系零偏、四元数、欧拉角/累计Yaw、温度与对应时间、融合方式、安装/磁标定确认、真实磁使用标志、丢帧/覆盖计数和重置序号。复制使用短 FreeRTOS 临界区，不在临界区内做浮点计算。getter 在复制后重新计算年龄，生产者暂停时不会一直返回旧的有效姿态；返回 true 只代表有快照，不代表姿态可用。

模式：INVALID 无有效解算；GYRO 为比力校正不可用的传播；SIX_AXIS 为惯性融合；NINE_AXIS 为本周期通过磁门控。`mag_valid` 只表示数据新鲜，是否参与校正还要看 `mag_calibrated` 与 `mag_used`。安装未确认时算法可运行，但 `attitude_valid` 永远为 false。

## MotionCal 磁场标定模式

2026-10-18按用户要求删除原Python拟合工具，改由固件输出MotionCal兼容数据，电脑端拟合硬铁/软铁参数。固件不接收MotionCal的 `Send Cal` 二进制包，也不写Flash；参数由人工回填。标定模式只改变日志分类和磁反馈许可，不创建任务，不停止原有电机任务。

### 开启和连接

1. 在 `Core/Inc/app/log/log_config.h` 将 `LOG_INS_MAG_CALIBRATION_ENABLE` 设为 `1U`，保持 `LOG_GLOBAL_ENABLE=1`、`LOG_USART1_ENABLE=1`。模式独立于TASK开关，并自动屏蔽其他分类，USART1只输出 `Raw:` 行。当前用户已设为1，标定结束后改回0；修改后重新编译、烧录。
2. **官方MotionCal使用115200/8N1，当前用户生成的 `.ioc`与 `usart.c`均已为115200。** 本次格式修复无需再次生成；改变波特率时见 [手动步骤](../../CUBEMX_MANUAL_STEPS.md#motioncal-标定时临时修改-usart1)。串口助手若占用COM需先关闭，再在MotionCal的Port菜单选择同一COM。
3. 下载入口为 [PJRC MotionCal](https://www.pjrc.com/store/prop_shield.html)。连接后，固件默认每100 HAL ms最多提交一个新磁样本；无需等待IMU静止校准完成。磁传感器未就绪、通信失败、数据过期或没有新样本时不伪造帧。

输出示例（芯片原始值为 `[-139,-105,224] LSB`）：

```text
Raw:0,0,0,0,0,0,-417,-315,672
```

**帧内不能有空格，必须保留结尾 `\r\n`。** 官方 `serialdata.c::ascii_parse()`进入RAW状态后，遇空格即跳到fail，只有CR（0x0D）会提交9字段，LF（0x0A）仅忽略。2026-10-18用官方解析器复现了旧格式40字节整帧拒收；删除9个空格后31字节成功进入官方磁标定缓冲。串口助手能显示文本不代表MotionCal接受格式。

PJRC解析器的字段顺序是 `ax,ay,az,gx,gy,gz,mx,my,mz`；前六项固定0，仅作磁标定占位，不表示真实加速度/角速度，界面姿态动画不作为本机姿态验证。后三项是**未减硬铁、未乘软铁、未安装旋转**的IST8310芯片系磁场。MotionCal按0.1μT/count解释整数，IST8310为0.3μT/LSB，所以输出 `raw × 3`，不是芯片raw直出，也不是μT乘1000。整数没有“三位数”的格式要求。

实现先扩展到32位long再乘3；若任一轴不能落入MotionCal的int16范围，则整帧丢弃，不能钳位或回绕。对应芯片值允许范围为每轴[-10922,+10922] LSB，超出通常表示严重干扰或异常数据，先检查环境。每行一次提交给唯一USART1 DMA后端，忙时丢帧、不排队、不阻塞融合，也不覆盖仍在发送的缓冲区。`INS_MAG_CALIBRATION_PERIOD_MS`默认100ms、有效范围>=100ms，间隔更大则采样更慢。成功提交后才标记该磁时间戳已发送；时间0和HAL回绕按独立状态及无符号差处理。

### 采集和回填参数

1. 保持最终安装的传感器与附近固定金属组合不变，缓慢覆盖三个轴正负方向。建议60~120s；只转Yaw或小范围Pitch不能完成三维软铁标定。机械行程不足时需在允许条件下转动整个固定组合，不能为了采样拆开会影响磁场的部件。
2. 观察MotionCal球面覆盖和右侧 `Gaps / Variance / Wobble / Fit Error`。本次核对的官方版本启用Send Cal的参考条件是分别低于15%/4.5%/4%/5%；它们是质量参考，不保证电机运行时无动态干扰。覆盖不足、参数不稳定或误差大时补采，不能沿用旧Python脚本的覆盖拒绝机制；固件不执行三维拟合或覆盖评估。
3. 将右侧 `Magnetic Offset` 的X/Y/Z依次填入任务配置中的 `INS_MAG_BIAS_UT`。界面已经显示μT，**直接填写，不再除10、不再乘0.3、不提前反转Y/Z**。将 `Magnetic Mapping` 的3×3矩阵按界面行列填入 `INS_MAG_SOFTIRON`，无量纲，不转置。
4. 保持 `corrected_chip = softiron × (mag_chip_ut - bias_ut)`，随后才乘 `INS_MAG_ROTATION`。不要用文章里的演示参数，也不要把MotionCal报告的场强当作偏置或矩阵。
5. 保存记录后，将 `LOG_INS_MAG_CALIBRATION_ENABLE` 改回0；确认参数有效后将 `INS_MAG_CALIBRATED` 改为1。需要恢复USART1 9600时再经CubeMX保存并生成。重新编译、烧录，保持静止约2s完成启动零偏。标定模式即使原配置已置 `INS_MAG_CALIBRATED=1`，运行时仍强制禁用磁反馈，输出始终来自未经校正的芯片数据。
6. 安装方向实测完成后再设置 `INS_MOUNT_CONFIRMED=1`；该门与磁标定独立。查看快照中的 `mag_used`，比较电机断电、通电及各转角下的场强和姿态。明显随电流/角度变化的磁干扰不能只靠一套固定偏置和软铁矩阵消除。所有参数目前仅保存在编译配置。
