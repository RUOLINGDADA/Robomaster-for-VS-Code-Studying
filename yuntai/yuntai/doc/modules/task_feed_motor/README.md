# 供弹电机自循环测试

文件名和 FreeRTOS 入口保留 `task_feed_motor`，因为它们必须匹配 CubeMX 创建的任务；模块内部的宏、类型、静态变量统一使用 `FEED_MOTOR`/`FeedMotor`，表示唯一的供弹电机。

## 任务行为

任务启动后注册 CAN1 上唯一的 M2006 供弹电机（ID 1），然后按以下顺序循环：

```text
等待有效反馈
    ↓
上弹：+3000 原始电流，2000 ms
    ↓
停止：0 电流，500 ms
    ↓
下弹：-3000 原始电流，2000 ms
    ↓
停止：0 电流，500 ms
    └────────────── 回到上弹
```

收到有效反馈前任务保持输出关闭并持续发送零电流。通信超时后驱动进入离线状态，任务回到等待反馈阶段。

## 为什么需要这些 Tick 变量

FreeRTOS 的任务不是“延时一次就结束”，而是每隔一段时间重复执行。因此代码里有三种互不相同的时间需求：

- `g_feed_phase_start_tick`：记录当前阶段从什么时候开始，用来判断上弹 2000 ms、停止 500 ms 或下弹 2000 ms 是否完成。阶段切换时必须重新赋值，否则新阶段会继承旧阶段的已运行时间。
- `g_feed_last_log_tick`：限制串口日志频率。任务每 2 ms 运行一次，但日志每 500 ms 打印一次；如果共用阶段计时或每轮都打印，USART DMA 会被大量日志占满，影响任务周期。
- `last_wake_tick`：`vTaskDelayUntil()` 的周期锚点。它只负责让任务按 2 ms 节拍醒来，和电机阶段持续时间、日志时间没有关系。使用固定锚点可以避免任务计算耗时造成周期逐轮漂移。

`TickType_t` 保存的是 FreeRTOS Tick 计数，不是毫秒。`FEED_MOTOR_*_TIME_MS` 是给人看的毫秒参数，运行时通过 `pdMS_TO_TICKS()` 转成 Tick。当前工程 Tick 频率为 1000 Hz，所以通常 1 ms 对应 1 Tick；使用转换宏可以避免以后修改系统 Tick 频率时阶段时间失效。Tick 计数会回绕，代码使用无符号差值计算间隔；测试阶段只有几秒，远小于回绕周期，因此跨回绕仍能得到正确的短时间间隔。

## 各阶段的意义

`WAIT_FEEDBACK` 不是多余的初始化状态。它确认 CAN 接收中断、电机 ID、反馈帧和驱动注册都已经工作；在确认之前保持零电流，避免 CAN 线断开时直接驱动电机。

`UP` 和 `DOWN` 分别使用正、负电流验证供弹机构的两个方向。它们各自有独立持续时间，便于观察实际机械运动，也方便以后分别调节两个方向的测试时间。

两个停止阶段都输出零电流。它们用于消除电机惯性和齿轮间隙带来的瞬时冲击，让机构在反向前短暂卸力；同时把上弹和下弹的边界变得清楚，串口日志也能明确显示当前是否处于停止阶段。两个阶段虽然输出相同，但必须分开命名，因为它们之后分别转入下弹和上弹。

任务每轮都调用 `C610_M2006_SendAll()`，因为 CAN 电流指令需要周期刷新。任务发现反馈超时后会关闭输出并清零目标，防止通信中断后继续沿用旧电流。

## 接入文件

- `Core/Src/task/task_feed_motor.c`：任务实现、CAN FIFO0 回调和测试阶段状态机。
- `Core/Src/freertos.c`：CubeMX 生成任务声明、任务创建和 weak 默认实现。
- `Core/Inc/usart.h`：`usart_printf()` 公共声明。
- `Core/Src/usart.c`：USART1 DMA 格式化输出实现。

`task_feed_motor.c` 提供同名强定义，会覆盖 `freertos.c` 中的 `__weak task_feed_motor_entry()`。这样重新生成 FreeRTOS 代码时，任务实现仍留在独立模块中。

## 参数调整

在 `task_feed_motor.c` 顶部调整：

```c
#define FEED_MOTOR_ID 1U
#define FEED_MOTOR_UP_CURRENT_RAW 3000
#define FEED_MOTOR_DOWN_CURRENT_RAW (-3000)
```

如果实机上弹和下弹方向相反，交换两个电流宏的正负值。第一次上电建议保持较小电流，确认机械方向、减速箱和限位条件后再提高。

## 串口输出

USART1 使用 115200 baud，日志通过 `usart_printf()` 走 DMA 发送：

- 阶段切换时打印一次，例如 `phase=up`、`phase=down`；
- 每约 500 ms 打印一次角度、转速、电流、温度和原始错误字节；
- CAN 接收中断不打印，避免在 ISR 中格式化字符串和等待 UART DMA。

## 运行前提

- CAN1 已由 `main.c` 初始化、启动并打开 FIFO0 pending 中断；
- CAN 过滤器已经接收目标反馈帧；当前工程使用全接收过滤器，后续可收窄到 `0x201` 至 `0x208`；
- USART1 和其 TX DMA 已初始化；
- C610/M2006 的设备 ID 与任务宏一致；
- 电机机械结构允许正反转，测试现场有人值守并准备断电。

## 任务上下文

任务周期为 2 ms，使用 `vTaskDelayUntil()` 保持周期。CAN 接收由 `HAL_CAN_RxFifo0MsgPendingCallback()` 完成；该回调只调用驱动取帧，不发送日志。任务优先级和栈大小来自当前 CubeMX 配置：优先级 26、栈深度 256 words。
