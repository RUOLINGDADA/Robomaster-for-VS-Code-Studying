# DBUS 鼠标跟手速度

鼠标相对位移按实际接收帧间隔换算成速度。新帧替换本轴速度，反向立即变号，零位移新帧直接清零。云台任务继续积分速度命令，零速度保持最后目标姿态。原始合法帧在 DBUS 邮箱内的位移求和仍然保留，避免任务延迟丢失输入。

实测日志、修改依据和实际 C 回放见[输入对比报告](input_trace_analysis_20261019.md)。用户已选择跟手模式；原累计算法的参数和验证记录属于历史。

## 接口和归属

- 接口：`Core/Inc/algorithm/mouse_virtual_joystick/mouse_virtual_joystick.h`；实现：对应 `Core/Src/algorithm/` 目录。
- `MouseVirtualJoystick_Init(handle, config)`：复制并检查配置；失败使句柄失效并清零。
- `MouseVirtualJoystick_Reset(handle)`：清除输出、时间与帧去重历史，保留有效配置。
- `MouseVirtualJoystick_Update(handle, now_ms, frame_sequence, frame_timestamp_ms, mouse_x, mouse_y, online, &x, &y)`：返回浮点千分比输出；失败清零输出及历史。

模块不依赖 HAL、FreeRTOS、CAN 或 UART，由 `task_dbus` 单任务独占实例。调用方一次取得 DBUS 快照，再取 HAL ms；帧时间和当前时间必须同源。算法不修改目标姿态、PID、重力补偿、限位或电流 Ramp。

## 测速公式和参数

对新帧或任务一次消费的合法帧批次：

```text
dt_ms = 当前批末帧接收时间 - 上次消费的末帧接收时间
v = clamp(delta_count × signed_gain × reference_period_ms / dt_ms, -limit, +limit)
```

`delta_count` 是本批位移代数和。多帧延迟消费时，分子和分母覆盖同一批间隔。首帧及两帧同属一个 HAL ms、无法得到非零间隔时，用参考周期作分母。计算使用接收时间差，不使用 2 ms 调度周期；重复帧只推进缺帧回中，不再次消费位移。时间和帧序号支持 uint32_t 正常回绕。

参数唯一入口为 `Core/Inc/task/task_dbus/task_dbus_config.h`，任务组装值副本传给算法：

| 参数 | 当前值、单位与范围 | 直接作用 |
| --- | --- | --- |
| `DBUS_MOUSE_VIRTUAL_REFERENCE_PERIOD_MS` | 14 ms，1~INT32_MAX | 增益对应的参考周期；增大同比提高测速输出 |
| `DBUS_*_MOUSE_VIRTUAL_GAIN_PERMILLE_PER_COUNT` | 两轴均 5.0 ‰/count，有限非负 | 参考周期下每 count 的命令；增大会提高灵敏度和触顶概率 |
| `DBUS_*_MOUSE_VIRTUAL_SIGN` | Yaw=-1、Pitch=+1 | 只改变鼠标输入方向 |
| `DBUS_*_MOUSE_VIRTUAL_HOLD_MS` | 两轴均 14 ms，可为 0 | 无新帧时从最后非零接收时刻开始保持；零位移新帧直接清零 |
| `DBUS_*_MOUSE_VIRTUAL_DECAY_MS` | 两轴均 14 ms，>0 | 缺帧保持结束后的回中时长；与保持之和不超过 INT32_MAX |
| `DBUS_MOUSE_VIRTUAL_OUTPUT_LIMIT_PERMILLE` | 300‰，1~1000 | 只限制鼠标分量；两轴满输入 40 rpm 时对应最高 12 rpm，即 72°/s |
| `DBUS_MOUSE_VIRTUAL_ENABLE` | 1，0/1 | 关闭时清鼠标状态，摇杆正常发布 |

例如连续两帧间隔均为 14 ms，X 位移均为 20 count：每帧均输出 -100‰，不会累加到 -200‰。下一帧 X=-1 时输出 +5‰；再下一帧 X=0 时立即输出零。28 ms 累计 40 count 同样输出 -100‰。小数直接进入速度命令，不取整回写。

当前增益表示每个参考周期内的位移测速增益。调灵敏度优先改对应轴增益；参考周期用于规定单位，不建议同时调整两者。正常接收约 14 ms，一 count 对应约 1.2°/s 目标速度，60 count 达到300‰上限。用户反馈移动慢后，保留现有两轴5.0增益，将上限从100‰调至300‰，使目标速度上限由24°/s提高至72°/s；未触旧上限的小动作不因此加速。实际速度受闭环跟踪及人工限位影响，手感和带载制动待上板。

## 时序、状态和故障

新帧 X/Y 独立更新；本轴零值仅清本轴。没有新帧时，保持后按固定起点和绝对时间线性回零，重复调度不会改变回中时长。当前非零事件达到 28 ms 时输出为零，即使 DBUS 的 100 ms 离线判定尚未到期；实际清零发生在首个达到时限的任务周期。收到零帧则无需等此时限。

状态值维持 IDLE=0、HOLD=1、DECAY=2、INPUT=3。INPUT 表示本次消费非零输入；HOLD/DECAY 表示等待新帧及缺帧回中。状态只用于诊断，总体状态取两轴较高优先级，日志分别保留两轴阶段。

非法参考周期、保持/回中时间或非有限增益使初始化失败；任务拒绝负的产品增益，算法接收已带方向的有限增益。离线、未来时间、时间或序号回退、同序号改变接收时间、NaN/Inf/溢出计算以及非法输出指针均清状态。0 ms 和序号 0 都可有效。离线恢复首帧用参考周期测速，不继承旧速度。

任务按 `clamp(stick + mouse, -1000, +1000)` 发布两轴命令，时间戳仍是最后合法帧的接收时刻，重复调用不续期。摇杆死区/映射、供弹、底盘和控制器权限保持原有规则。人工命令边界过滤在云台控制层完成，鼠标限幅不裁剪自稳纠偏。

## 日志和验证

USART1 保持 921600/8N1，高密度采集继续开启。启动说明输出“鼠标=位移测速”、参考周期、增益、缺帧时序、方向和上限。R/C/S 字段与状态位编码不变，C 中“累计鼠标”表示本周期接收帧位移之和。字段、DWT 回绕和丢样检查见[DBUS 模块](../dbus/README.md#摇杆与鼠标输入采集)。

临时主机使用真实算法、DBUS 解码、任务适配与命令发布路径：旧算法在等速不累加、反向、零帧及时间归一化四项行为检查失败；当前算法通过。共 22664 项检查，覆盖实际日志回放、批量输入、重复帧、小数、极值、非法配置、独立轴、缺帧、离线/恢复和时序回绕；919 条实测摇杆命令逐条不变。更新后的日志头和模拟 921600 baud、5 秒持续输入无新增丢样。

主机替身不验证真实 HAL DMA 时延和机械响应。仅交付源码，由用户在 VS Code 构建烧录；未生成固件。先在中位分轴做慢移、快移、反向和停手，确认目标跟手后再测双轴及人工边界。真实带载停止、Pitch 挡块余量和六轴保持精度仍待实测。
