# yuntai 工程上下文

## 当前边界

- 本文档对应目录：`yuntai/yuntai`。
- 同级父目录包含多个独立学习示例；它们是参考资料，不属于本工程的构建输入。
- `can_example` 是当前代码风格和 RoboMaster CAN 设备封装的主要参考工程。

## 已确认的工程状态

- MCU/芯片：STM32F407，使用 STM32 HAL 和 CMSIS。
- RTOS：FreeRTOS，工程同时生成了 CMSIS-RTOS V2 适配层。
- 构建：CMake + Ninja 预设，工程名为 `yuntai`。
- 当前生成代码包含 `main.c`、`freertos.c`、GPIO 初始化和 FreeRTOS 默认任务；业务模块尚未接入。
- 目前应把新增业务代码放入 `Core/Inc`、`Core/Src` 的 `bsp/` 或 `app/` 子目录，并接入 CMake。

## 目标架构

```text
硬件/协议驱动（bsp） -> 功能模块（app） -> FreeRTOS 任务与系统入口
```

驱动负责寄存器、HAL、协议帧解析和最小状态；功能模块负责把一个或多个驱动组合成可运行的行为；任务负责调度和跨模块通信。业务逻辑不得直接散落在 HAL 回调中。

## 参考代码边界

`can_example` 中的 C620 驱动展示了句柄、命令表、CAN 帧和回调的写法，但当前工程只按实际功能采用其中的必要部分。没有明确用途的错误枚举、回调、日志和状态层不应直接复制。

## 交付要求

每次改动都要说明：改动文件、公开接口、任务/中断上下文、硬件假设、构建或静态检查结果、未验证风险和后续问题。需求未明确时，把问题写入 `OPEN_QUESTIONS.md` 并在回复中直接询问。
