# GM6020 CAN 驱动

## 模块边界

源码位于：

```text
Core/Inc/bsp/gm6020/gm6020.h
Core/Src/bsp/gm6020/gm6020.c
Core/Src/bsp/can/can_rx_dispatch.c
```

驱动只负责 GM6020 协议和最小设备状态：解析 `0x205~0x20B` 反馈、累计连续编码器角度、记录反馈时间、判断在线超时、保存目标电流、聚合发送电流控制帧 `0x1FE/0x2FE` 以及执行软件硬限位。它不读取遥控器，不运行 PID，不判断“操作者是否仍在向挡块方向操作”，也不打印串口。

云台轴的动态堵转判定在 `Core/Src/app/gimbal/gimbal_protection.c`，因为它必须同时知道命令方向、启动/换向宽限、控制器输出和恢复策略。通用驱动不能把这些任务语义伪装成 GM6020 协议错误。

## 反馈与发送协议

| 字段 | 值 |
| --- | --- |
| 标准反馈 ID | `0x205~0x20B`（电机 ID 1~7） |
| Yaw 默认 ID | `0x205` |
| Pitch 默认 ID | `0x206` |
| 电流控制帧 ID | `0x1FE`（电机 ID 1~4）、`0x2FE`（电机 ID 5~7） |
| 电压控制帧 ID | `0x1FF`/`0x2FF`，本驱动不发送 |
| 数据长度 | 8 字节 |
| `DATA[0:1]` | 单圈角度，取低 13 位，`0~8191` |
| `DATA[2:3]` | 有符号转速，rpm |
| `DATA[4:5]` | 有符号反馈电流原始值 |
| `DATA[6]` | 温度，摄氏度 |
| `DATA[7]` | 保留字段；驱动只保存原始字节，不把它当作通用错误码 |

依据 `参考文档/markdown/RoboMaster_GM6020----------20231013.md`：GM6020
电流给定范围为 `[-16384, 16384]`，对应最大转矩电流约 `[-3 A, 3 A]`；
`0x1FE/0x2FE` 才是电流控制帧，`0x1FF/0x2FF` 是电压控制帧。此前参考工程中的
`±30000` 注释与该官方手册冲突，不能继续用于本驱动。C620/3508 的 `±16384`
和 C610/M2006 的 `±10000` 仍分别按各自手册处理，不能跨型号复用。

所有双字节字段均为高字节在前。STM32F407 是小端 CPU，因此实现逐字节组合，不能把 `DATA` 地址强转成 `int16_t *`；强转还会引入未对齐访问和字节序错误。

`0x205`（电机 ID 1）写入 `0x1FE` 的 `DATA[0:1]`，`0x206`（电机 ID 2）写入
`0x1FE` 的 `DATA[2:3]`。Yaw 和 Pitch 共享同一电流控制帧，驱动每次发送都会从
静态注册表聚合句柄；如果以后注册 ID 5~7，则另外聚合到 `0x2FE`，不能把高组槽位
继续写入 `0x1FE` 的 8 字节数组。

## 公开 API 与上下文

- `Gm6020_Init()`：任务或普通初始化上下文注册句柄；不启动 CAN。
- `Gm6020_SetCurrent()`、`Gm6020_SetOutputEnabled()`：任务上下文修改 RAM 中的目标；必须由 `Gm6020_Send()` 周期发送。
- `Gm6020_HandleRxMessage()`、`Gm6020_RxFifoCallback()`：CAN FIFO 回调中调用，只解析和记录，不打印、不阻塞。
- `Gm6020_Process()`：任务上下文使用 `HAL_GetTick()` 更新在线和硬限位状态。
- `Gm6020_GetSnapshot()`：任务读取与同一次反馈更新对应的一致快照。
- `Gm6020_Send()`：任务上下文周期发送 `0x1FE` 和/或 `0x2FE` 电流控制帧；
  `0x1FF/0x2FF` 电压控制帧不由本接口发送。
- `Gm6020_SetMechanicalLimit()`：设置连续编码器角度上下限；没有标定值时传禁用常量。
- `Gm6020_ClearAngleLimit()`：只清除驱动层软件限位锁，不自动重新使能输出；云台运行时只在明确向内意图下调用。

`Gm6020_ConfigTypeDef` 的角度参考字段用于固定机械标定：`angle_reference_single_raw`
是中心对应的单圈值，`angle_reference_total_raw` 是中心对应的连续值，
`angle_reference_enabled` 决定首帧是否按该参考重建连续坐标。参考中心必须来自实机标定。首次上电位置必须相对中心处于半圈以内（严格小于 4096 计数），驱动才能用最短回绕差值唯一确定首帧所在连续位置；机械总行程不由这个条件限制。

## CubeMX 任务接入

当前 `yuntai.ioc` 的 FreeRTOS 任务记录为：

| Task name | Entry function | 作用 | 建议栈 |
| --- | --- | --- | --- |
| `task_yaw` | `task_yaw_entry` | 云台底盘水平轴，GM6020 `0x205` | 384 words |
| `task_pitch` | `task_pitch_entry` | 发射云台纵向轴，GM6020 `0x206`，默认只读标定 | 384 words |

如果用 CubeMX 图形界面重新创建，必须把任务放在同一组 `FREERTOS.Tasks01` 中，任务名和入口函数按表填写；不要手写多个 `Tasks02/Tasks03` 字段，否则 CubeMX 可能只识别第一组。`freertos.c` 只负责创建任务并提供 `__weak` 空实现，强入口由 CMake 加入的任务目录源文件覆盖。重新生成后检查 `FREERTOS.Tasks01`、`MX_FREERTOS_Init()` 和链接列表三处是否一致。

### 为什么需要快照

CAN ISR（中断服务程序）可能正在依次写角度、转速、电流和温度。如果任务逐字段读取句柄，日志可能出现“新角度配旧电流”的混合帧。接收函数在写入前后递增 `feedback_sequence`，任务复制前后比较序列号，并用 `__DMB()` 保证内存访问顺序；序列号变化或为奇数时丢弃本次复制。`volatile` 只保证序列号每次从内存读取，不自动让多字段结构体原子化，因此仍必须使用这个复制协议。

## 连续角度与软件边界

GM6020 单圈计数为 8192。相邻两帧角度差大于半圈时，驱动把它解释为 `8191→0` 或 `0→8191` 的回绕，再累加到 `angle_total_raw`。如果该轴已完成标定，首帧会以标定中心为参考重建连续角度；否则仍以首帧单圈值作为临时起点。

标定后的范围由各轴 task_yaw_config.h 或 task_pitch_config.h 提供：

```text
min_angle_raw <= target/current <= max_angle_raw
```

用户先通过只读标定测试记录中位和左右/上下安全边界，将边界按计数排序后写入本轴配置，并将本轴 *_CALIBRATION_VALID 改为 1。驱动首帧使用“最接近标定中心的回绕值”，因此上电位置必须能在中心半圈内唯一解释。驱动硬限位只负责安全清零输出，方向相关的释放由通用云台轴保护层决定。

## 超时与 CAN 分发

反馈时间戳由 `HAL_GetTick()` 写入，`Gm6020_Process()` 也必须接收同一时基的当前值；不能把 `xTaskGetTickCount()` 直接与它相减。时间差使用无符号减法，允许短间隔跨计数回绕。超时（默认 100 ms）会将目标电流清零、关闭输出并进入离线状态；任务仍应持续发送零电流控制帧。

`can_rx_dispatch.c` 只从 FIFO0 取出一次帧，再按 CAN 句柄分发给 GM6020 和 C610/M2006。多个驱动不能各自调用 `HAL_CAN_GetRxMessage()` 抢同一个 FIFO，否则后调用者会丢帧。

## 与通用轴保护层的关系

通用轴的堵转候选必须同时满足：输出已使能、目标电流达到最小驱动力、反馈电流达到阈值、速度低、连续角度在窗口内变化不足、启动/换向宽限结束，并连续保持检测时间。确认后进入 `GIMBAL_PROTECTION_STALL_HOLD`，持续零输出。

保护不会按固定时间盲目重新加电。正式相对命令模式同向保持零输出，松手/反向且电流下降持续确认后解除，并以当前实际角度重置保持点。固定目标模式只能由手动反向移开达到距离、范围内、新鲜反馈、电流下降持续确认后解除；解除先清历史并发送零，再追踪原目标。CAN 掉线不清除堵转保持。保护原因和事件快照只在任务上下文打印。

## 已知限制与验证

- `0x205` 与 C610/M2006 的 ID 5 在同一 CAN 总线上冲突；当前供弹电机使用 ID 1（`0x201`）。
- GM6020 手册规定有效电机 ID 为 1~7（反馈 `0x205~0x20B`），本工程默认只注册
  Yaw/Pitch 两个句柄；驱动注册表虽支持完整协议范围，但不代表必须接满 7 个电机。
- 使用电流控制前必须在 RoboMaster Assistant 中确认电机固件已打开电流环；手册注明
  该功能需要对应固件和软件版本。若设备仍处于电压控制模式，不能把 `int16_t` 电流
  数值直接当成有效转矩命令。
- 堵转阈值、恢复距离与确认时间是各轴配置中的台架起点，不是 GM6020 的通用标准。
- 反馈在线、连续角度和快照一致性可做静态/合成帧验证；机械边界、电流方向、物理堵转和温升必须在可急停台架实测。
- 构建验证使用：`cmake --preset Debug`、`cmake --build --preset Debug`。当前机器若没有 CMake，至少执行项目记录的 `arm-none-eabi-gcc -fsyntax-only` 检查。

## 硬件调参测试

永久测试代码与驱动同级：

| 文件 | 用途 |
| --- | --- |
| `bsp/gm6020/test_gm6020_calibration.*` | 强制零电流，手动记录中心、最小和最大连续角度。 |
| `bsp/gm6020/test_gm6020_angle_loop.*` | 使用通用正式轴运行时保持各轴配置目标角度，观察到达、保持和手动拨离恢复。 |

Yaw/Pitch 任务分别通过本轴 `*_HARDWARE_TEST_MODE` 选择标定、角度环或正式模式，不再使用测试套件。
角度目标由对应轴配置中的目标宏设置，单位是相对标定中心的度数；
PID、Ramp、限位和堵转保护全部来自正式运行时。纯协议和算法边界验证使用临时脚本，
不提交为永久测试文件。所有硬件测试都必须有人值守并准备急停。

## 双轴共用测试 API 与并发约束

`Gm6020_CalibrationTypeDef` 位于驱动头文件，正式模式和测试共用一份中心/边界。
测试函数参数分别传入电机、标定、共用轴运行时和独立测试状态；测试头文件不包含任何任务头文件。
每轴任务初始化一次，周期直接调用 `Gm6020_TestCalibration_Run()` 或 `Gm6020_TestAngleLoop_Run()`。

控制周期通过 `Gm6020_GetSnapshot()` 复制一次，计算、保护及日志复用 `axis.cycle`；串口忙时重试，
不会重新取得下一帧。首帧时间戳可能为 0 ms，`feedback_received` 单独表明是否收到过有效帧。
`online` 根据有效反馈和 HAL 毫秒年龄判断，关闭输出不会把离线电机变成在线。

`Gm6020_Send()` 聚合所有同总线句柄，并在保存/恢复 PRIMASK 的短临界区中构建与提交帧。
该临界区不等待发送完成；返回 true 只表示交给 HAL 邮箱。每轴只由自己的任务修改电流，
注册/注销也在临界区内完成。角度硬限位阻止向外电流，向内意图可由上层解除锁后脱离。

固定目标测试不是遥控松手。确认堵转后持续零电流，需向触发方向反向移开 114 计数（默认约 5°）、
反馈新鲜、实际电流下降且仍处于安全范围内，再确认 100 ms。掉线保留锁存但重置连续确认计时；
解除时清 PID/Ramp 并先完成零输出周期。传动比或边界实际值由各轴实测记录决定。
