**一、整体链路**

```text
.c / .cpp / .s 源码
   ↓ 编译
.o / .obj 目标文件
   ↓ 链接，按 linker script 分配地址
.elf + .map
   ↓ objcopy 提取可烧录内容
.bin / .hex
   ↓ 烧录到 Flash
上电 / 复位
   ↓
Bootloader 或 App 的 Reset_Handler
   ↓
初始化 .data / .bss
   ↓
main()
```

`.o/.obj` 是中间文件；`.elf` 是带符号、段信息、调试信息的完整可执行文件；`.map` 是内存分布报告；`.bin/.hex` 通常是真正烧录进 Flash 的镜像。

**二、没有 Bootloader 时的 Flash / RAM**

```text
Flash 0x08000000
+-----------------------------+
| .isr_vector                 | 中断向量表，含初始 SP 和 Reset_Handler
| .text                       | 函数代码
| .rodata                     | 字符串字面量、const 数据
| .data 的加载初值             | 已初始化变量的初始值模板
+-----------------------------+

RAM 0x20000000
+-----------------------------+
| .data                       | 已初始化全局/static变量的运行实体
| .bss                        | 未初始化/初始化为0的全局/static变量
| heap                        | malloc/new
| stack                       | 局部变量、调用现场
+-----------------------------+
```

关键点：

```text
.text / .rodata：通常直接在 Flash 里执行/读取
.data：Flash 里有初值，main 前复制到 RAM
.bss：Flash 里通常没有实际 0 内容，main 前只把 RAM 对应区域清零
```

`.bss` 不是从 Flash 拷贝到 RAM 再清零，而是**只根据链接器给出的 RAM 地址范围清零**。

**三、main 前启动代码做什么**

复位后 CPU 先从向量表取：

```text
vector[0] = 初始栈指针 MSP
vector[1] = Reset_Handler 地址
```

然后执行 `Reset_Handler`：

```c
extern uint32_t _sidata;  // Flash 中 .data 初值起点
extern uint32_t _sdata;   // RAM 中 .data 起点
extern uint32_t _edata;   // RAM 中 .data 终点
extern uint32_t _sbss;    // RAM 中 .bss 起点
extern uint32_t _ebss;    // RAM 中 .bss 终点

void Reset_Handler(void)
{
    uint32_t *src = &_sidata;
    uint32_t *dst = &_sdata;

    while (dst < &_edata) {
        *dst++ = *src++;
    }

    dst = &_sbss;
    while (dst < &_ebss) {
        *dst++ = 0;
    }

    main();
}
```

所以进入 `main()` 前，RAM 中的 `.data` 已经有正确初值，`.bss` 已经全是 0。

**四、加入 Bootloader 后的 Flash 布局**

有 Bootloader 时，Flash 通常被人为分区：

```text
Flash
0x08000000
+-----------------------------+
| Bootloader 区               |
| boot .isr_vector            |
| boot .text                  |
| boot .rodata                |
| boot .data 初值              |
+-----------------------------+
| App 区                      |
| app .isr_vector             |
| app .text                   |
| app .rodata                 |
| app .data 初值               |
+-----------------------------+
| 参数区 / 升级标志 / 校准值   |
+-----------------------------+
| 备份 App / OTA 镜像          |
+-----------------------------+
```

例如：

```text
Bootloader: 0x08000000 ~ 0x08003FFF
Application: 0x08004000 ~ ...
Config: 某个 Flash 页
```

这时 App 的链接地址不能再从 `0x08000000` 开始，而要从 `0x08004000` 开始。App 的 linker script 也要改。

**五、Bootloader 的启动流程**

上电后，CPU 通常先从 `0x08000000` 取向量表，所以先进入 Bootloader：

```text
上电 / 复位
   ↓
CPU 读取 Bootloader 向量表
   ↓
进入 Bootloader Reset_Handler
   ↓
Bootloader 初始化自己的 .data / .bss
   ↓
进入 Bootloader main()
   ↓
检查是否升级、校验 App 是否有效
   ↓
如果 App 有效，跳转到 App
```

注意：Bootloader 也是一个完整程序，它也有自己的：

```text
boot .text
boot .rodata
boot .data
boot .bss
boot stack
```

Bootloader 进入自己的 `main()` 前，也会先复制自己的 `.data`、清零自己的 `.bss`。

**六、Bootloader 跳转 App 时发生什么**

App 区开头也有自己的向量表：

```text
App Base = 0x08004000

0x08004000: App 初始 MSP
0x08004004: App Reset_Handler 地址
```

Bootloader 跳转 App 时，典型操作是：

```c
#define APP_BASE 0x08004000UL

typedef void (*entry_t)(void);

void jump_to_app(void)
{
    uint32_t app_msp   = *(uint32_t *)(APP_BASE + 0);
    uint32_t app_reset = *(uint32_t *)(APP_BASE + 4);

    __disable_irq();

    SCB->VTOR = APP_BASE;      // Cortex-M：切换中断向量表到 App
    __set_MSP(app_msp);        // 设置 App 的栈指针

    ((entry_t)app_reset)();    // 跳到 App Reset_Handler
}
```

跳过去后，不是直接进 App 的 `main()`，而是进入 **App 的 Reset_Handler**。  
然后 App 会重新做自己的：

```text
复制 app .data：Flash App 区初值 -> RAM
清零 app .bss：RAM 对应区域写 0
初始化运行库
进入 App main()
```

所以加入 Bootloader 后，完整流程变成：

```text
上电
 ↓
Bootloader Reset_Handler
 ↓
初始化 Bootloader 的 .data / .bss
 ↓
Bootloader main()
 ↓
判断升级 / 校验 App
 ↓
跳转 App Reset_Handler
 ↓
初始化 App 的 .data / .bss
 ↓
App main()
```

**七、Bootloader 和 App 的 RAM 关系**

Bootloader 和 App 通常共用同一块 RAM。

Bootloader 运行时：

```text
RAM
+-----------------------------+
| boot .data                  |
| boot .bss                   |
| boot heap/stack             |
+-----------------------------+
```

跳到 App 后，App 的启动代码会重新初始化自己的 RAM 区域：

```text
RAM
+-----------------------------+
| app .data                   |
| app .bss                    |
| app heap/stack              |
+-----------------------------+
```

因此一般不要指望普通 RAM 内容从 Bootloader 自动保留到 App。  
如果确实要传递信息，常见做法是：

- 用固定 RAM 地址
- 用 `.noinit` 段
- 用备份寄存器
- 用 Flash 参数区
- 用 RTC backup domain

**八、变量和段的详细对应**

| 写法                            | 典型段                        | Flash 镜像 | RAM 运行时            |
| ----------------------------- | -------------------------- | -------- | ------------------ |
| `void foo(void)`              | `.text`                    | 有代码      | 通常无                |
| `static void foo(void)`       | `.text`                    | 有代码      | 通常无                |
| `const int g = 1;`            | `.rodata`                  | 有        | 通常无                |
| `static const int s = 2;`     | `.rodata`                  | 有        | 通常无                |
| `"hello"`                     | `.rodata`                  | 有        | 通常无                |
| `int g = 1;`                  | `.data`                    | 有初值      | 有变量实体              |
| `static int s = 2;`           | `.data`                    | 有初值      | 有变量实体              |
| `int g;`                      | `.bss`                     | 通常无实际内容  | 有变量实体，启动清零         |
| `static int s;`               | `.bss`                     | 通常无实际内容  | 有变量实体，启动清零         |
| `int g = 0;`                  | 通常 `.bss`                  | 通常无实际内容  | 有变量实体，启动清零         |
| `int local = 1;`              | 栈/寄存器                      | 无固定镜像    | 函数运行时临时存在          |
| `const int local = 1;`        | 可能立即数                      | 可能无      | 可能无独立内存            |
| `static int local = 3;`       | `.data`                    | 有初值      | 有变量实体              |
| `static const int local = 4;` | `.rodata`                  | 有        | 通常无                |
| `char arr[] = "abc";`         | `.data`                    | 有初值      | 有可修改数组             |
| `const char *p = "abc";`      | p 在 `.data`，字符串在 `.rodata` | 都有相关内容   | p 在 RAM，字符串在 Flash |

特别注意：

```c
const char *p = "abc";
```

这里是两个东西：

```text
p 这个指针变量：.data，运行时在 RAM
"abc" 字符串字面量：.rodata，通常在 Flash
```

而：

```c
char arr[] = "abc";
```

`arr` 是数组本体，可修改，所以运行时在 RAM 的 `.data`。

**九、局部变量为什么可能没有内存**

```c
void foo(void)
{
    const int a = 1;
    bar(a);
}
```

优化后可能直接变成：

```text
把立即数 1 传给 bar
```

这时：

```text
a 不在 Flash
a 不在 RAM
a 不在栈
a 只是编译器源码层面的名字
```

如果取地址：

```c
printf("%p\n", (void *)&a);
```

编译器通常必须给 `a` 一个真实地址，常见是在栈上。  
`(void *)` 是因为 `%p` 规范上要求传 `void *`。

**十、显式放到 RAM 执行的函数**

普通函数默认在 Flash 的 `.text` 执行。  
如果写：

```c
__attribute__((section(".ramfunc")))
void flash_erase_func(void)
{
}
```

则通常变成：

```text
Flash：保存 .ramfunc 的加载内容
启动时：复制 .ramfunc 到 RAM
运行时：CPU 从 RAM 执行该函数
```

常见原因：

- 擦写 Flash 时，Flash 忙，不能同时从 Flash 取指
- 需要更快执行
- 需要稳定时序

**十一、linker script 里怎么看**

典型链接脚本片段：

```ld
.text :
{
    *(.isr_vector)
    *(.text*)
    *(.rodata*)
} > FLASH

.data :
{
    _sdata = .;
    *(.data*)
    _edata = .;
} > RAM AT > FLASH

.bss :
{
    _sbss = .;
    *(.bss*)
    *(COMMON)
    _ebss = .;
} > RAM
```

解释：

```text
.text > FLASH
表示代码和只读数据运行/存放在 Flash

.data > RAM AT > FLASH
表示 .data 运行地址在 RAM，但加载初值在 Flash

.bss > RAM
表示 .bss 只在 RAM 占空间，启动时清零
```

这里的两个概念很重要：

```text
VMA：运行地址
LMA：加载地址
```

`.data`：

```text
VMA = RAM
LMA = Flash
```

`.bss`：

```text
VMA = RAM
LMA = 没有实际初始化内容
```

**十二、map 文件里还会看到什么**

| 段                                | 作用                              |
| -------------------------------- | ------------------------------- |
| `.debug_*`                       | 调试信息，给 IDE/GDB 看，通常不进烧录镜像       |
| `.symtab` / `.strtab`            | 符号表、字符串表，工具用                    |
| `.comment`                       | 编译器版本等信息                        |
| `.ARM.exidx` / `.ARM.extab`      | ARM 异常展开/回溯                     |
| `.init_array`                    | `main()` 前要执行的初始化函数表，C++ 全局构造常用 |
| `.fini_array`                    | 程序结束析构表，裸机少用                    |
| `.noinit`                        | RAM 中不清零区域，复位后可保留值              |
| `.ramfunc`                       | 需要搬到 RAM 执行的函数                  |
| `.text.*` / `.data.*` / `.bss.*` | 细分子段，最后归并到对应大段                  |

**十三、最终总图**

```text
Flash
+------------------------------------------------+
| Bootloader .isr_vector / .text / .rodata       |
| Bootloader .data 初值                           |
+------------------------------------------------+
| App .isr_vector / .text / .rodata              |
| App .data 初值                                  |
+------------------------------------------------+
| 参数区 / 升级标志 / 校准值 / 备份镜像           |
+------------------------------------------------+

启动时：
1. CPU 先进 Bootloader
2. Bootloader 初始化自己的 .data/.bss
3. Bootloader 判断是否跳 App
4. 跳 App Reset_Handler
5. App 初始化自己的 .data/.bss
6. App 进入 main()

RAM：
+------------------------------------------------+
| 当前正在运行程序的 .data                       |
| 当前正在运行程序的 .bss                        |
| heap                                           |
| stack                                          |
| 可选 shared/noinit 区                           |
+------------------------------------------------+
```

最准确的总结是：

**Flash 里保存 Bootloader、App、只读数据、代码、`.data` 初值和参数区；RAM 里保存运行时可修改数据、栈、堆。上电后先执行向量表指向的 Reset_Handler，启动代码负责复制 `.data`、清零 `.bss`。有 Bootloader 时，Bootloader 先初始化并运行，再跳到 App 的 Reset_Handler，由 App 再初始化自己的运行环境，最后才进入 App 的 `main()`。**
