# C620/M3508 CAN 驱动

接口位于 `Core/Inc/bsp/m3508_c620/m3508_c620.h`，实现位于对应 `Core/Src/bsp/` 目录。驱动只管理协议、注册表、一致快照和聚合电流，不读取 DBUS、不运行 PID、不创建任务、不配置过滤器。四个 CAN1 句柄由 `task_chassis` 长期持有。

## 协议与来源

移植依据为只读源工程 `MyChassis1-main/MyChassis1-main/Core/Src/bsp/m3508_c620/` 及其 C620 CAN 文档。C620 标准数据帧固定 8 字节，反馈 ID 为 `0x200+电调ID`。当前板级过滤器只接收 ID1~4 的 `0x201~0x204`。驱动协议层支持 ID1~8；若以后使用 ID5~8，必须同时扩展 CAN1 硬件过滤器。

| 字节 | 含义 | 单位/范围 |
|---|---|---|
| 0~1 | 大端单圈转子角度 | 0~8191 count；越界整帧拒绝 |
| 2~3 | 大端有符号转子速度 | rpm，轮轴速度需除减速比 |
| 4~5 | 大端有符号反馈电流 | raw；保留协议原始值 |
| 6 | 电机温度 | ℃，沿用源 C620 协议资料 |
| 7 | 原始状态字节 | 固件解释待确认，原样保存，不参与保护 |

控制 `0x200` 对应 ID1~4，`0x1FF` 对应 ID5~8，每个槽位为大端有符号电流。C620 协议电流限制为 ±16384 raw（约 ±20 A），底盘实际进一步限制为 ±4915 raw（约 ±6 A）。不能使用 C610 的 ±10000 raw 边界。CAN2 的 C610 虽使用相同 ID，但被接收分发层与驱动注册表按总线隔离。

## API 与并发

- `C620_M3508_Init/DeInit`：任务注册/撤销长期句柄；同总线 ID 和地址不能重复。容量为 8；参数或注册失败不改调用者句柄。注销不自动发送，当前仅用于初始化回滚。
- `C620_M3508_HandleRxMessage`：唯一 FIFO0 回调取得一帧后在 ISR 调用，验证总线、标准数据帧、DLC、ID 与角度；不再读取 FIFO，不打印或等待。
- `C620_M3508_GetSnapshot`：任务复制全部反馈，随后在同一短 PRIMASK 临界区读取 HAL ms，计算年龄及在线门。`received=false` 表示没有真实首帧，0 ms 时间戳本身有效。
- `SetOutputEnabled/SetCurrent`：任务保存许可和电流；使能需要真实新鲜反馈，拒绝或禁用同时清电流。写电流不会自动使能。
- `InvalidateFeedback`：Bus-Off 清首帧标志与电流，恢复必须收到新帧。
- `SendAll`：任务在一个短临界区内遍历本总线、复核反馈新鲜度和 BOFF、构建并提交 HAL。超时槽位强制零，未注册槽位为零。每个使用组提交一帧；本底盘只使用 `0x200`。

注册、复制、许可和构建到提交均保存/恢复 PRIMASK；ISR 更新期间任务不能复制半帧。临界区内只有有限遍历与 HAL 非阻塞邮箱提交，禁止日志、等待和重试。邮箱忙/HAL 失败返回 false，下一底盘周期发送最新值；HAL 接受不等于电调已执行。ABOM 恢复由 CAN1 硬件完成，驱动不会停止或重置 CAN2。

## 验证

临时原生 C 替身验证首帧门、0 ms、正负大端、角度/帧校验、双总线同 ID 分发、注册拒绝、协议限流、发送时超时、邮箱失败、Bus-Off 与时间回绕。Debug 构建通过。实际收发器、终端电阻、固件字节 7 语义及电流换算仍待实机复核。
